[m] maijevFROM MANUAL TO AUTOMATED

把四个问题，拆成四项独立任务

字幕过碎

从词级时间戳构造 atom，单独让模型决定合并分组。

人名识别错误

结合可选 OCR、cast 名单和全文，生成共享词库；允许人工覆盖。

长段输出不稳定

自动分批、校验响应、处理失败，缓存已完成的部分。

SRT 格式与时间码

模型只返回分组或 id + 译文，程序负责时间轴与最终渲染。

这些是视频中描述的早期使用体验，不是对今天 Whisper、CapCut 或所有字幕工具的统一评价。

工程化减少重复操作，不取消人工校对03 / 12

MERGE / 合并

哪些相邻 atom 放在一起？

0 | s1 | 今日は
1 | s1 | よろしくお願いします。

{"groups": [[0, 1]]}

start = atom[0].start
end   = atom[1].end

检查连续性、重复 id 与静音跨度，取首尾 atom 的时间。

TRANSLATE / 翻译

这个 id 对应哪句中文？

0  今日はよろしくお願いします。

{"lines": [
  {"id": 0, "zh": "今天请多关照"}
]}

原 start + 原 end + 中文译文

校验 id 覆盖情况；空译文回退原文，避免静默丢行。

以上 JSON 与字幕为结构示意，不是质量评测样本05 / 12

[m] maijevLONG-FORM WORKFLOW

长视频，不必每次从头来

01 / TRANSCRIBE

识别独立切片

在静音附近切成约 5 分钟片段。ASR chunk 独立缓存与重试，复用成功结果。

02 / RESUME

缓存跟着内容走

合并、翻译与 pre-pass 的缓存考虑输入、提示词与模型，配置变化不会静默命中旧结果。

03 / REVISE

改词库，再重翻

GUI 中编辑人工词库并保存重翻，复用识别与合并，把新的调用留给翻译。

[m] maijevLIMITATIONS

结构可校验，内容仍需要判断

程序能控制的

  • 字幕分组与 id 对齐的结构检查
  • 不让 LLM 重写最终时间码
  • 分阶段缓存与可重复的处理流程
  • 同一份词库注入各翻译批次

仍需人工留意的

  • ASR 内容、词级时间戳的误差
  • 人名推断、双关、漫才与视觉笑点
  • 跨 chunk 的说话人身份不保证一致
  • 阅读节奏与最终字幕质量

当前翻译是纯文本调用：OCR 提供画面文字线索，
但不等于让模型理解完整画面、动作与语气。

自动化减少重复劳动，不意味着免校对发布10 / 12
[m] maijevGET STARTED

先跑通主干，再接入词库与 OCR

准备环境

  • Python ≥ 3.13、uv
  • ffmpeg / ffprobe
  • OpenRouter key：用于 MAI ASR
  • 推荐 Gemini key：用于合并与翻译

CLI 与可选 Web GUI 共用同一流水线。
支持本地音视频与 yt-dlp 远程来源。

# 在项目目录安装依赖
uv sync

# 在 .env 配置 API keys 后运行
uv run python -m flows.maijev.pipeline \
  input.mp4 \
  runs/example \
  --translate --prepass

# 输出
out.srt
out_llm_ja.srt
out_zh.srt
